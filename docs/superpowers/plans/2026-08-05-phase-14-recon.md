  production Dockerfile, no spcs_spec.yaml, no deploy/backup runbooks, no
  smoke.md. Root `Dockerfile` is the LEGACY Streamlit app's — don't touch.
- Compose now runs FIVE services incl. P13's `worker` — doc 07 §4 and doc
  08 P14 both predate P13 and name only backend+db+minio for the spec. The
  P14 gate requires distillation firing → the spec needs the worker
  resolved explicitly (4th container vs folded process). Genuine
  doc-vs-reality gap to resolve in the plan.

  deliberately doesn't migrate. Ontology mounted at /ontology because
  loaders resolve repo-root-relative (parents[4]/parents[3]) — real image-
  layout hazard for the production Dockerfile.

  BACKUP_TARGET, RETENTION_*. `deploy_mode="spcs"` literal exists but
  nothing keys off it in the data layer; NO snowflake client exists
  (core/data/client.py:11 "a later task"); live_chat's snowflake guard
  fires on `data_backend != "synthetic"` → P14 stays synthetic.
- No snowflake-snowpark-python / snowflake-connector-python dependency yet.
- **No Snowflake account on this machine** (Carlos's explicit E3 deferral,
